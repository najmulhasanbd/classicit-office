Executive Summary

Orchestrating High-Volume Commerce at Scale

Global Digital Retail Ltd. operates an expansive multi-vendor e-commerce marketplace catering to over 1,200 verified independent merchants and more than 45,000 active daily shoppers across retail fashion, electronics, and fast-moving consumer goods.

When sudden viral flash sales and nationwide shopping holidays caused continuous database contention, gateway timeouts, and overselling anomalies in their legacy application, Classic IT was commissioned as the primary architectural partner to design, build, and deploy a modern, distributed commerce infrastructure.

The Technical Challenge

The client's existing commerce stack struggled under three compounding systemic bottlenecks:

Inventory Race Conditions

Multiple buyers simultaneously checked out the last available stock item during flash sales, resulting in embarrassing order cancellations and customer frustration.

Monolithic Database Locks

Cart queries, product catalog browsing, and heavy merchant analytics shared a single database replica, which locked tables and caused page load times to exceed 8 seconds.

Architecture & Engineering Execution

Classic IT's senior technical architects restructured the application into a resilient, event-driven microservices architecture:

1. Microservices Decomposition & Read/Write Segregation

Separated product catalog search, customer authentication, checkout, and merchant payout ledger into independent containerized microservices. Implemented CQRS (Command Query Responsibility Segregation) with read replicas.

2. Atomic Redis Distributed Stock Locking (Redlock)

Engineered memory-speed stock reservation using Redis atomic lua scripts with a 10-minute cart TTL. If checkout isn't completed, stock is automatically released back to inventory without database table contention.

3. Multi-Gateway Payment Router & Automated Webhooks

Configured dynamic smart payment routing across bKash, Nagad, Visa, Mastercard, and SSLCommerz. If one payment provider experiences gateway latency, the system automatically redirects payments with zero basket abandonment.

4. Automated Merchant Commission & Escrow Ledger

Developed an immutable double-entry ledger that calculates tiered merchant commissions, tracks holding periods, handles partial refunds, and executes automated BEFTN bank payout batch files.
